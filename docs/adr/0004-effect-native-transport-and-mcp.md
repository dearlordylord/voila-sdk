# An Effect transport port, and an MCP server that is Effect all the way down

The SDK's transport is an Effect service, not a promise-returning port, and the MCP server is `@effect/ai`'s. The only promise crossing left in the workspace is the CLI's outermost entry point, whose contract is promise-shaped by nature.

Decisions:

- **`VoilaTransport` is a `Context.Tag`.** An operation is an `Effect` requiring the transport; a program provides one layer and every operation inside it uses that transport. A transport argument threaded through every operation made each call site decide the adapter, and made the SDK's own composition (a paginating scan, a bootstrap followed by a read) carry a parameter that has nothing to do with the domain.
- **The adapter's failure vocabulary is three tags, and carries no request material.** `VoilaRequestDeadlineExceeded`, `VoilaConnectionFailure`, and `VoilaResponseReadFailure`. A caller distinguishing a refused connection from an exceeded deadline is deciding whether to retry; a caller reading a URL, a cookie, or a header out of an error is reading a secret. The deadline carries `timeoutMs` and nothing else.
- **The deadline is an Effect timeout, not an `AbortSignal` port.** It runs on the Effect Clock, so a test drives it with `TestClock` instead of waiting on wall-clock time, and interrupting the waiting fiber aborts the underlying request rather than leaving a socket open. That matters because a Voila request runs inside the session-file update cycle and holds that file's lock while it does: an abandoned-but-live request is not one slow tool call, it is every tool call in the process queued behind it. The body is read under the same deadline as the headers — a response that stalls after its headers holds the lock exactly as long as one that never answers. The bound is per request, not per operation: a paginating operation such as `voila_get_completed_order_items` issues one request per order it reads, so its worst-case lock hold is that request count times the deadline.
- **A request body carries its own content type.** `HttpClientRequest` applies the body after the headers, and a body built without a content type rewrites `content-type` to `text/plain`. The adapter reads the content type off the request's headers and builds the body with it, so a JSON write reaches Voila as JSON.
- **The MCP server is `@effect/ai`'s `McpServer`.** It is built on `@effect/rpc`, so no `@modelcontextprotocol/*` package is a dependency and no hand-written JSON Schema bridge sits between the Effect Schemas and the wire: `Tool.make` publishes the schema the operation actually decodes. Tools are declared as `Tool.make(name, { parameters: SomeSchema.fields, ... })`, because `Tool.make` wraps `parameters` in `Schema.Struct` itself and rejects an already-built struct.

Protocol shape, as `@effect/ai` serves it:

- `tools/list` emits draft-07 JSON Schema with no `$schema` marker. `additionalProperties: false`, refinement bounds, and `properties: {}` for a parameterless tool all survive; per-field `title`/`description` strings derived from refinements are added. Tests pin the constraints that decide what a client may send, not the absent marker.
- A schema-violating call and a failing operation are both normal tool results with `isError: true` at HTTP 200, never JSON-RPC protocol errors. The text half of a result is the compact `JSON.stringify` of the value — the old server hand-rolled a 2-space pretty form, so protocol tests pin substrings and structure, not the exact rendering. The decode failure surfaces as an `AiError` whose `description` embeds the raw arguments — acceptable here because no tool takes a secret as an argument, and worth remembering if one ever does.
- Omitting `arguments` entirely is rejected as a JSON-RPC error wrapping a defect. The MCP schema declares the field required; a parameterless tool is called with `arguments: {}`.
- HTTP is stateless per POST: no `mcp-session-id` is issued or required, and a mismatched `mcp-protocol-version` header is ignored. The server negotiates down to `2025-06-18`. Because there is no session gate on the wire, the HTTP transport refuses any request carrying a non-local `Origin` header: binding to loopback is not protection on its own, and the tools mutate a real cart.

Consequences: protocol tests drive the real server rather than a mock — over HTTP through `NodeHttpServer.layerTest`, and over stdio through a `PassThrough` pipe pair, since `layerStdio` takes Effect streams and `@effect/ai` ships no client to drive it with. `@effect/ai` is 0.x and its API is moving to Effect 4's `effect/unstable/ai`; the version is pinned exactly, and the upgrade is expected to be a rename of the import surface against the same `Toolkit`/`McpServer` concepts. The risk is accepted because the alternative — a hand-maintained JSON Schema bridge over the official SDK — is the code this decision deletes.
